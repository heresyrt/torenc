# 토목·건설 기업 소개 웹사이트 설계 명세

## 목표

토목·건설 기업을 위한 현대적인 반응형 한국어 웹사이트를 제작한다. `torenc.com`의 정보 구조만 참고하며 시각 디자인, 문구 구성, 코드는 새롭게 작성한다. 첫 번째 버전은 데이터베이스와 관리자 기능이 없는 정적 데이터 기반 기업 홍보 사이트로 구현한다.

## 언어 원칙

사이트의 기본 언어는 한국어이며 HTML 문서 언어를 `ko`로 지정한다. 화면 문구, 메타데이터, 대체 텍스트, 접근성 레이블, 오류 및 안내 문구, README 문서는 모두 자연스러운 한국어로 작성한다. 코드 식별자와 파일명은 생태계의 일반적인 영문 표기 규칙을 따르되, 사용자가 접하는 영역에는 불필요한 영어를 사용하지 않는다.

## 시각 방향

딥 네이비를 기반으로 따뜻한 콘크리트 회색, 흰색 여백, 절제된 안전 오렌지 포인트를 사용한다. 크고 기술적인 타이포그래피, 얇은 그리드 선, 명확한 섹션 번호, 넉넉한 간격으로 기존 사이트를 모방하지 않으면서 신뢰감 있고 정밀하며 현대적인 엔지니어링 기업 이미지를 만든다.

최종 사진을 받기 전에도 페이지가 완성도 있게 보이도록 구성한다. 이미지 위치에는 카테고리와 권장 비율이 표시된 의도적인 플레이스홀더를 사용한다. 플레이스홀더가 실제 이미지와 동일한 공간을 예약하므로 나중에 이미지를 교체해도 레이아웃이 밀리지 않는다.

## 정보 구조

단일 페이지 사이트는 다음 순서로 구성한다.

1. 데스크톱 내비게이션과 접근성 높은 모바일 메뉴를 포함한 고정 헤더
2. 기업 핵심 문구, 주요 행동 버튼, 비주얼 예약 영역이 있는 히어로
3. 핵심 수치를 포함한 회사 소개
4. 사업 분야 카드
5. 시공 실적 갤러리
6. 인증서 및 보유 기술 갤러리
7. 교체 가능한 정적 지도 컴포넌트를 포함한 오시는 길
8. 문의 유도 영역
9. 기업 정보 푸터

내비게이션 링크는 의미 있는 섹션 랜드마크로 스크롤한다. 모바일 메뉴는 항목 선택 시 닫히고 `Escape` 키를 지원하며, ARIA 속성으로 열림 상태를 알리고 키보드 포커스를 명확하게 표시한다.

## 기술 구조

Next.js 최신 안정 버전의 App Router, TypeScript, Tailwind CSS를 기반으로 한다. 모든 정적 섹션은 기본적으로 서버 컴포넌트로 렌더링한다. 클라이언트 컴포넌트는 모바일 메뉴와 Intersection Observer 기반 노출 효과처럼 상호작용이 필요한 부분으로 제한하며 별도의 애니메이션 라이브러리는 사용하지 않는다.

콘텐츠, 내비게이션, 사업 분야, 핵심 수치, 시공 실적, 인증서, 연락처, 메타데이터는 타입이 지정된 `src/data/site-data.ts`에 둔다. 재사용 가능한 표현 컴포넌트는 기업 문구를 직접 포함하지 않고 이 데이터를 전달받아 렌더링한다. 공통 TypeScript 인터페이스는 `src/types/site.ts`에 둔다.

전체 페이지 조립은 `src/app/page.tsx`에서 담당한다. 공통 UI는 `src/components/ui`, 전역 내비게이션은 `src/components/layout`, 페이지 섹션은 `src/components/sections`에 배치한다. 지도는 독립 컴포넌트로 분리해 향후 카카오맵이나 네이버지도 구현으로 교체해도 오시는 길 섹션을 변경하지 않도록 한다.

## 이미지 전략

초기 갤러리는 임의의 스톡 이미지 대신 전용 플레이스홀더를 렌더링한다. 각 데이터 항목은 선택적 이미지 경로, 한국어 대체 텍스트, 원본 너비와 높이, 블러 데이터 URL을 가질 수 있다. 이미지 경로가 제공되면 공통 미디어 컴포넌트가 `next/image`를 사용해 품질 90, 정확한 반응형 `sizes`, 고정된 화면 비율 래퍼, 카테고리에 맞는 `object-cover` 또는 `object-contain`을 적용한다.

파일은 다음과 같이 정리한다.

- `public/images/hero`: 히어로 사진, 2400×1600 이상 권장
- `public/images/projects`: 시공 사진, 2000×1250 이상 권장(16:10)
- `public/images/certificates`: 인증서 스캔, 1600×2200 이상 권장
- `public/images/og`: 소셜 공유 이미지, 1200×630

파일명은 영문 소문자 케밥 표기와 의미 있는 접두사를 사용한다. 예: `project-retaining-wall-jeju-01.webp`. 이미지 준비 과정에서 고화질 원본은 별도로 보존하며, 실제 표시 크기보다 작은 해상도로 과도하게 축소하지 않는다. 배포 파일은 고품질 WebP, AVIF, JPEG 또는 PNG를 사용할 수 있다.

## 반응형 동작

모바일 우선으로 설계한다. 콘텐츠는 최대 너비가 지정된 중앙 컨테이너와 유동적인 간격을 사용한다. 카드는 작은 화면에서 1열, 태블릿에서 2열, 데스크톱에서 최대 3열로 배치한다. 헤더는 데스크톱 기준점 아래에서 오버레이 형태의 내비게이션 패널로 전환된다. 갤러리 이미지는 모든 화면 너비에서 카테고리별 비율을 유지한다.

## 애니메이션과 접근성

Intersection Observer를 이용한 절제된 노출 효과를 사용하고 요소가 처음 노출된 후에는 관찰을 해제한다. 자바스크립트가 없어도 콘텐츠는 기본적으로 표시되어야 한다. `prefers-reduced-motion: reduce` 환경에서는 움직임을 제거한다.

의미에 맞는 제목과 랜드마크, 버튼, 한국어 레이블, 설명적인 한국어 대체 텍스트, 충분한 색상 대비, 본문 바로가기, `focus-visible` 스타일, 키보드 조작 가능한 내비게이션을 제공한다. 장식 요소는 보조 기술에서 숨긴다.

## 검색 최적화와 성능

루트 메타데이터에는 한국어 제목 및 설명 형식, 대표 URL, Open Graph, Twitter 카드, 검색 노출 설정을 포함한다. App Router 메타데이터 라우트로 `sitemap.xml`과 `robots.txt`를 생성한다. 페이지에는 하나의 H1과 논리적인 제목 계층을 사용한다.

서버 렌더링, 최소한의 클라이언트 자바스크립트, 시스템 또는 로컬 글꼴, 안정적인 미디어 크기, 반응형 이미지 규격, 절제된 애니메이션으로 Core Web Vitals를 보호한다. 플레이스홀더는 이미지 요청을 발생시키지 않는다. 실제 이미지가 추가되면 히어로를 제외한 이미지는 지연 로딩하며, 히어로 이미지는 필요 시 우선 로딩한다.

## 오류 및 대체 동작

이미지 경로가 없는 항목은 의도적인 플레이스홀더를 표시한다. 콘텐츠 데이터는 정적으로 타입 검사하여 잘못된 항목이 빌드 전에 발견되게 한다. 외부 지도와 문의 전송 기능은 이번 버전에서 연결하지 않는다. 지도 제공자가 없어도 주소와 교통 안내는 표시하며, 문의 영역은 전화와 이메일 직접 링크를 사용한다.

## 테스트 및 검증

Vitest와 Testing Library로 데이터 기반 섹션 렌더링, 모바일 메뉴의 접근성 상태, 플레이스홀더와 실제 이미지 선택, 지도 대체 콘텐츠를 검사한다. 각 동작은 구현 전에 테스트를 작성하고 예상한 이유로 실패하는 것을 확인한 후 구현한다. 완료 조건은 테스트, ESLint, TypeScript 타입 검사, Next.js 프로덕션 빌드가 모두 성공하는 것이다. 데스크톱과 모바일 화면에서 가로 넘침, 포커스 동작, 레이아웃 안정성, 가독성도 직접 확인한다.

## 문서화

README는 한국어로 작성하며 필요한 실행 환경, 설치 방법, 개발 및 프로덕션 명령어, 콘텐츠 수정법, 이미지 폴더 위치, 파일명 규칙, 권장 원본 크기, 지도 제공자 교체 방법, 남은 회사별 결정 사항을 설명한다. 관리자 페이지와 데이터베이스가 이번 범위에 포함되지 않는다는 점도 명시한다.

## 제외 범위

- 데이터베이스, CMS, 관리자 CRUD
- 문의 폼 백엔드와 이메일 발송
- 카카오맵 또는 네이버지도 API 키 및 실제 연동
- 최종 사진, 인증서, 법적 기업 정보, 확정된 운영 문구
- 별도의 상세 페이지와 다국어 라우팅
