# 확대 뷰어 원본 이미지 로딩 설계

## 목표

모바일 확대 뷰어에서 CSS 확대 시 발생하는 흐림을 줄인다. 목록 카드와 썸네일의 전송량은 현재 수준으로 유지하고, 사용자가 확대 뷰어를 연 이미지에 한해서 원본 파일을 내려받는다.

## 범위

- 갤러리 목록과 썸네일은 기존 `next/image` 최적화를 유지한다.
- 확대 뷰어의 주 이미지는 `/public`의 원본 경로를 직접 사용한다.
- 원본은 뷰어가 열린 뒤에만 요청한다.
- 원본 해상도가 낮은 이미지도 동일하게 처리하며, 이번 작업에서는 업스케일이나 이미지별 확대 제한을 추가하지 않는다.

## 동작 설계

확대 뷰어가 열리면 기존과 같은 레이아웃 안에 원본 이미지를 표시한다. 브라우저가 `/images/...` 파일을 직접 요청하도록 하여 Next.js 이미지 변환 결과가 아니라 저장된 원본 픽셀을 사용한다. 이미지의 화면 맞춤, 핀치 확대, 이동, 이전·다음 전환 동작은 유지한다.

목록 카드와 하단 썸네일은 계속 `next/image`를 사용하므로 페이지 진입 시 모든 원본이 다운로드되지 않는다. 활성 이미지가 바뀌면 새 활성 이미지의 원본만 요청한다. 브라우저 캐시는 같은 이미지를 다시 열 때의 재다운로드를 줄인다.

## 구현 경계

- 변경 중심: `src/components/ui/content-gallery.tsx`
- 확대 뷰어의 주 이미지에만 원본 직접 로딩을 적용한다.
- 갤러리 데이터 구조, 제스처 계산, 확대 배율 상수는 변경하지 않는다.
- 원본 이미지 파일 자체는 변경하거나 재압축하지 않는다.

## 접근성 및 오류 처리

- 기존 대체 텍스트와 드래그 방지 동작을 유지한다.
- 원본 요청이 실패해도 다이얼로그를 닫거나 다른 이미지로 이동할 수 있어야 한다.
- 이미지 레이아웃 크기를 데이터의 `width`와 `height`로 유지해 로딩 중 레이아웃 이동을 방지한다.

## 검증

- 컴포넌트 테스트에서 확대 뷰어의 주 이미지가 Next.js 최적화 URL이 아닌 원본 `src`를 사용하도록 보장한다.
- 목록 이미지와 썸네일은 기존 동작을 유지하는지 확인한다.
- 기존 확대·이동·스와이프 테스트를 모두 실행한다.
- 린트, 타입 검사, 전체 테스트를 실행한다.

## 제외 사항

- 저해상도 원본 교체
- AI 업스케일
- 이미지 포맷 변환 및 압축률 조정
- 이미지별 최대 확대 배율 변경
