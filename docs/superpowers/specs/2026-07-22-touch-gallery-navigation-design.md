# 터치 중심 갤러리 탐색 설계

## 목표

전체 화면 갤러리의 별도 확대·축소 버튼과 이전·다음 버튼을 제거한다. 모바일 사용자는 브라우저의 기본 핀치 제스처로 화면을 확대하고, 한 손가락 좌우 스와이프로 사진을 이동한다. 데스크톱 키보드 탐색과 기존 접근성 동작은 유지한다.

## 인터랙션

- 상단의 축소, 100% 초기화, 확대 버튼과 확대 비율 표시는 제거한다.
- 상단에는 현재 사진 제목, `현재 순서 / 전체 개수`, 닫기 버튼만 표시한다.
- 하단의 이전·다음 버튼은 제거한다.
- 이미지 영역에서 한 손가락을 수평으로 충분히 이동하면 해당 방향의 다음 사진을 연다.
- 오른쪽에서 왼쪽으로 스와이프하면 다음 사진, 왼쪽에서 오른쪽으로 스와이프하면 이전 사진을 연다.
- 첫 사진의 이전과 마지막 사진의 다음은 기존처럼 반대편 끝으로 순환한다.
- 두 손가락 이상의 입력은 갤러리 이동으로 처리하지 않고 브라우저의 기본 핀치 확대에 맡긴다.
- 짧은 터치와 수직 이동은 사진 이동으로 처리하지 않는다. 스와이프는 최소 수평 이동 거리를 넘고 수평 이동량이 수직 이동량보다 클 때만 인정한다.

## 데스크톱과 접근성

- `ArrowLeft`와 `ArrowRight` 키를 이용한 사진 이동을 유지한다.
- `Escape` 닫기, 열릴 때 닫기 버튼으로 포커스 이동, 닫힐 때 원래 카드로 포커스 복귀를 유지한다.
- 화면에 이전·다음 버튼이 없어도 현재 순서는 텍스트로 계속 제공한다.
- 닫기 버튼과 인증서의 원본 PDF 열기·다운로드 링크는 유지한다.

## 구현 구조

기존 `ContentGallery` 안의 `activeIndex`와 순환 이동 함수는 재사용한다. 별도 확대 비율 상태와 확대 관련 키보드 처리, 이미지 너비 변환은 삭제한다.

이미지 영역에는 터치 시작점과 유효한 단일 터치 여부를 저장한다. 터치 종료 시 수평·수직 이동량을 비교해 조건을 만족할 때만 기존 이동 함수를 호출한다. 멀티터치가 시작되거나 진행 중 감지되면 해당 제스처의 스와이프 판정을 취소한다. 브라우저 기본 확대를 막는 `preventDefault`는 사용하지 않는다.

## 예외 처리

- 항목이 하나뿐이면 스와이프해도 같은 항목을 유지한다.
- 터치가 취소되면 저장한 시작점을 폐기하고 이동하지 않는다.
- 스와이프로 사진이 바뀌면 이전 확대 비율을 초기화하는 별도 로직은 필요하지 않다. 확대는 브라우저가 관리한다.
- 스와이프 판정은 이미지 영역에만 적용해 닫기 버튼이나 PDF 링크 조작과 충돌하지 않게 한다.

## 테스트와 완료 조건

- 확대·축소·100% 버튼과 확대 비율이 렌더링되지 않는지 확인한다.
- 이전·다음 화면 버튼이 렌더링되지 않는지 확인한다.
- 충분한 좌우 단일 터치 스와이프가 사진을 순환 이동하는지 확인한다.
- 짧은 터치, 수직 제스처, 멀티터치는 사진을 이동하지 않는지 확인한다.
- 키보드 방향키 이동, `Escape` 닫기, PDF 링크 노출이 계속 동작하는지 확인한다.
- 관련 컴포넌트 테스트, 전체 테스트, ESLint, 타입 검사와 프로덕션 빌드가 통과해야 한다.
- 모바일 브라우저에서 핀치 확대, 좌우 스와이프, 닫기와 PDF 링크를 직접 확인한다.
